**Method:** Real Chromium via Playwright 1.63 (repo root), viewport 1440x900 desktop + 390x844 mobile, realistic Chrome UA, wait ~3s after load. All 5 references resolved status 200 — no bot-wall fallback to WebFetch was needed.

## Cross-cutting patterns (transferable)

1. **Huge, tight-tracked headline as the entire hero statement** — 64-96px with negative letter-spacing (Vercel/Linear/Notion/GitHub). Scales the brand promise before any scroll.
2. **Rigid 12-column grid** for all content below the hero (Vercel/Linear/GitHub) — order and precision, matches "Dark Precision Engineering".
3. **Scoped hover transitions** (Stripe: `color, background-color, border-color`; Linear: `color, background`) instead of blanket `all` — calmer, more purposeful motion. (GitHub/Vercel use `all` — a step worse.)
4. **Proof-by-artifact hero** (Stripe's simulated checkout) — demonstrate the capability inside a labeled UI object rather than asserting it.
5. **Dual CTA pattern** — one marketing/sales action + one self-serve/contact action, always visible in hero and header (Verle/Notion).
6. **Per-property transitions + one dark theme carried the whole page** (Linear) — consistency of surface beats novelty per section.
7. **Bottom retention hook** (GitHub newsletter, Notion quote+footer) — end the page with an offer or a voice, not just link columns.
8. **Use-case outcome cards with "→"** (Notion) — concrete named outcomes outperform generic "Features" list items.

## Explicit non-transfers (fabrication risk, per HARD RULES)
- **Customer/logo marquees** (Notion, GitHub "trusted by" strips) — would require inventing client names; do not copy.
- **Fabricated metrics** in any hero artifact — no made-up numbers; a demo artifact must be labeled as a demonstration.
